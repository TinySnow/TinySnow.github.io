+# ==============================================================================
+# 生成 src/last-updated.md
+#
+# 该脚本是 “最近更新” 页面生成器，输出结构固定为：
+# - H1 标题
+# - Prenote 提示
+# - 最近 N 次变更记录（默认 3 次，先进先出）
+#
+# 每条“变更记录”包含：
+# - 记录标题（本次变更总标题）
+# - Summary（生成时间、基准提交、diff 来源、统计）
+# - Index（文件索引 + +/-）
+# - 每个文件一个可折叠 diff 区块
+#
+# 支持两种 diff 来源：
+# 1) --staged（默认）
+#    基于 git 暂存区，适合本地预览“即将提交”的变化。
+# 2) --range "<A..B>"
+#    基于提交范围，适合 CI（与 GitHub Actions 事件 before..after 对齐）。
+#
+# 关键约束：
+# - 默认排除 src/last-updated.md（避免自引用递归膨胀）
+# - 默认排除 src/sitemap.xml（该文件时间戳噪音大，几乎每次都变）
+# - 保留 sitemap.txt（文章新增时具有信息价值）
+#
+# 历史保留策略：
+# - 默认最多保留 3 条记录（可通过 --history-limit 调整）
+# - 新记录始终在最上方
+# - 超出数量时淘汰最旧记录（FIFO）
+# - 前提：输出文件需要先包含“上一轮生成结果”（例如 CI 先恢复上一次 artifact）
+#   若每次都从一个固定旧模板起步，历史自然无法累计
+#
+# 依赖：
+# - git、bash、sed、awk、cksum、mktemp
+# ==============================================================================

+make_anchor() {
+  # 为每个文件生成稳定且可跳转的锚点 id。
+  # 规则：
+  # 1) 先把路径做 slug 化（仅保留字母数字，其他字符压成 -）
+  # 2) 再拼接 cksum，避免不同路径 slug 冲突
+  # 3) 再拼接 entry_key，避免不同“历史记录块”之间锚点冲突
+  local file_path="$1"
+  local index="$2"
+  local entry_key="$3"
+  local slug checksum
+
+  # sed 正则说明：
+  # - s/[^[:alnum:]]+/-/g: 将连续非字母数字字符压缩为一个 -
+  # - s/^-+//: 去掉开头连续 -
+  # - s/-+$//: 去掉结尾连续 -
+  slug="$(printf '%s' "${file_path}" \
+    | tr '[:upper:]' '[:lower:]' \
+    | sed -E 's/[^[:alnum:]]+/-/g; s/^-+//; s/-+$//')"
+  checksum="$(printf '%s' "${file_path}" | cksum | awk '{print $1}')"
+
+  if [[ -z "${slug}" ]]; then
+    slug="file-${index}"
+  fi
+
+  printf 'f-%s-%s-%s' "${entry_key}" "${slug}" "${checksum}"
+}

+stat_to_display() {
+  # 将 numstat 的统计值转换为可展示文本。
+  # numstat 对二进制文件会给 '-'，此处统一显示为 bin。
+  local value="$1"
+  # 正则 ^[0-9]+$ 用于区分普通文本行数与二进制占位符。
+  if [[ "${value}" =~ ^[0-9]+$ ]]; then
+    printf '%s' "${value}"
+  else
+    printf 'bin'
+  fi
+}

+collect_numstat() {
+  # 收集单文件的增删行数统计（added/deleted）。
+  # staged 与 range 模式分别走不同 git 命令，但输出格式统一为:
+  #   <added>\t<deleted>
+  local file_path="$1"
+  local line added deleted
+
+  if [[ "${MODE}" == "staged" ]]; then
+    line="$(git -C "${PROOT}" diff --cached --numstat -- "${file_path}" | head -n 1 || true)"
+  else
+    line="$(git -C "${PROOT}" diff --numstat "${GIT_RANGE}" -- "${file_path}" | head -n 1 || true)"
+  fi
+
+  added="$(printf '%s' "${line}" | awk '{print $1}')"
+  deleted="$(printf '%s' "${line}" | awk '{print $2}')"
+
+  if [[ -z "${added}" ]]; then
+    added="0"
+  fi
+  if [[ -z "${deleted}" ]]; then
+    deleted="0"
+  fi
+
+  printf '%s\t%s\n' "${added}" "${deleted}"
+}

+  # 这意味着调用方需要提供“上一轮已生成文件”作为输入基线。

+
+  if [[ ! -f "${source_file}" ]]; then

+  fi

+  while IFS= read -r line || [[ -n "${line}" ]]; do

+def run_git(*args: str) -> bytes:

+def iter_name_status_z(output: bytes):
+    """解析 git --name-status -z，兼容普通、重命名与复制状态。"""
+    fields = [part.decode("utf-8", errors="replace") for part in output.split(b"\0")]
+    index = 0
+    while index < len(fields) - 1:
+        status_token = fields[index]
+        if not status_token:

+        status_code = status_token[0]

+# 文章标题

+## 各部分格式规则
+
+### 标题与文件名
+
+- 正文第一行使用一级标题：`# 文章标题`。
+- 文件名通常取文章标题并以 `.md` 结尾，但会为了路径简洁而省略标题中的部分空格。例如标题中的 `llm` 或年龄前后可能有空格，文件名中没有。
+- 不要擅自把英文缩写改成大写；参考文章使用 `llm`。
+- `src/SUMMARY.md` 中展示的标题可以包含额外的视觉标记，例如重点文章前的 `⭐️`；该标记不一定属于正文标题或文件名。
+
+### “写在前面”
+
+- 固定标题为 `## 写在前面`。
+- 第一项通常是单行 HTML 段落，样式字符串应保持为：
+
+  ```html
+  <p style="color:#0f4c81; text-align:center; font-weight:bold; font-size:larger;">……</p>
+  ```
+
+- 内容格式通常是 `字数 字 | 标签一 | 标签二 | …`。
+- 字数与标签之间、标签彼此之间使用半角空格包围的竖线：` | `。
+- 字数应以最终正文为准计算，不能直接照搬微信公众号可能显示的旧字数。具体计数口径需要结合待提供的微信导出样本和用户期望再确定。
+- 如果文章另有阅读提示，可在标签行后增加普通居中 HTML 段落，例如：
+
+  ```html
+  <p style="text-align:center;">阅读提示。</p>
+  ```
+
+### 正文
+
+- 固定标题为 `## 正文`。
+- 普通中文正文段落以两个全角空格开头，即两个 U+3000 字符：`　　`。
+- Markdown 源码中，各段之间保留一个空行。
+- 不要把两个全角空格替换为四个半角空格、制表符或 HTML `&emsp;`。
+- 场景转换、较强的语义停顿或文末署名前，使用独占一行的 `<br />`；其前后各空一行。
+- 保留有意义的 Markdown 行内格式，包括：
+  - 加粗：`**文字**`
+  - 下划线：`<u>文字</u>`
+  - 加粗与下划线组合：`<u>**文字**</u>`
+  - 链接：`[文字](URL)`
+- 正文可以出现编号、引用内容和强调段，不应为了统一外观而删除原有语义格式。
+- 中文与英文缩写、阿拉伯数字之间的空格，应尽量沿用作者在现有文章中的写法，不做激进的自动排版或内容润色。
+- 转换工具的职责是格式迁移，不应未经要求改写措辞、修正观点或重组文章结构。
+
+### 署名与日期
+
+- 正文结束后通常先放一行 `<br />`。
+- 署名固定为：`　　南国微雪 Miyuki`。
+- 日期单独成段，格式通常为：`　　YYYY 年 M 月 D 日`。
+- 署名和日期均以两个全角空格开头，二者之间空一行。
+- 个别文章在日期之后还有地点或情境说明，应作为独立段落保留，并同样使用两个全角空格缩进。
+
+### “写在后面”
+
+- 此章节可省略。
+- 存在时固定标题为 `## 写在后面`，位置在署名日期之后、`## 封面图` 之前。
+- 内容可能是补充说明，也可能是正文配图；不得假设它一定是文字。
+
+### 封面图
+
+- 固定标题为 `## 封面图`。
+- 封面图片使用 Markdown 图片语法：`![](URL)`。
+- 当前文章的图片一般托管在 `https://img.tinysnow.cn/blog/articles/literature/` 下，但转换工具不应凭空生成文件名或 URL。

+
+  ```markdown
+  > 摄影师・画师 | 作者或来源
+  >
+  > 图源 | 平台或来源
+  ```
+
+- `摄影师・画师` 中间使用的是日文间隔号 `・`。
+- 作者和图源必须来自用户提供的信息或可验证的现有数据；缺失时应保留待填写项或明确提示，不能猜测。
+
+### SUMMARY 条目
+
+- 新文章最终应加入 `src/SUMMARY.md` 的“文章与写作”对应列表。
+- 链接路径相对于 `src/SUMMARY.md`，通常形如：
+

+- 章节结尾无法用一个自然问题引出下一章。

+
+　　有些人直来直去，很讨厌猜来猜去、阴晴不定的暧昧阶段。但是暧昧阶段也就这一点有意思了。两个人之间相互拉扯、相互抱有爱恋的猜忌。因为在乎对方，因为喜欢对方，才会不断内耗。
+
+　　然而，对有些人来说，在这个阶段体验到的内耗，远大于其体验到的幸福。
+

+## 正文
+
+　　“你永远无法叫醒一个装睡的人。”
+
+　　这句话其核心是因为，对方“睡觉”是出于选择。而人的主观能动性，一旦下定决心，很难改变。
+
+　　所以，当我们开始劝有些人的时候，比起不听，“假装听了”显得更加可恶。
+
+　　因为对方是主动选择了欺骗。
+
+　　“不听”在这种程度上居然会显得更加可爱一些，起码它诚实。
+
+　　“欺骗”与“诚实”看似只是一个选择，但并非是天平的两方。“欺骗”天生就意味着更高的辨别成本，而“诚实”则不涉及。为什么人们天生喜欢诚实的人，因为许多人天生怕麻烦。
+
+　　这也是为什么，那些“碟中谍”看起来要比“两个人互相表白心意”烧脑得多。这两种片子就是两个极端，一个无限猜忌和怀疑，套中套辨别成本指数爆炸，飞出天际，而一个只需要观察和祝福就好。
+
+　　如果非要对这种情形定性，这种应该是“坏”，是一种主观恶意。
+
+　　而另一种叫“蠢”。这种情况多半发生在“我以为我懂了”上面。
+
+　　“不懂”是一种诚实的客观情况，只要意识到了就有救，可以去学，可以求助，不至于误判情况。最起码，我们知道“我们需要审慎地观察当前的情况”。
+
+　　“以为懂了”危险就危险在，我们以为我们没有选择，于是朝着错误的道路上狂飙，但其实我们有选择，只是我们不知道。
+
+　　而这种“不知道”可以被修正，贵在“无意识”。它相比上面的“坏”，也就有救在这种地方——经过提点，能够挽救。
+
+　　但如果当“我以为我懂了”和“我不听”相互叠加的话，那就另说了，对方几乎已经主动关闭了所有纠错的可能。
+
+　　对于这种人，我们能选择的，大概只有“远离”、“审判”或“惩罚”了——放弃助人情结，尊重他人命运；做好风险隔离，静待现实审判。
+
+　　因为人最危险的时候，不是犯错的时候，而是失去了发现错误的能力的时候。
