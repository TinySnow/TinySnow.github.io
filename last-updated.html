+# 咬舌自尽的狗
+
+*林清玄*
+
+　　有一次，带家里的狗看医生，坐上一辆计程车。
+
+　　由于狗咳嗽得很厉害，吸引了司机的注意，反身问我：“狗感冒了吗？”
+

+
+　　司机突然长叹一声：“唉！咳得和人一模一样呀！”
+

+

+

+

+
+　　计程车司机虽然十分讶异，但是他二话不说，又从家里拿出布袋，把狼狗装入布袋，再次带去放生，这一次，他从北宜公路狂奔到宜兰，一路听到狼狗低声号哭的声音。
+
+　　到宜兰山区，把布袋打开，发现满布袋都是血，血，还继续从狼狗的嘴角流溢出来。他把狗嘴拉开，发现狼狗的舌头断成两截。
+
+　　原来，狼狗咬舌自尽了。
+

+

+
+　　司机说，他把狼狗厚葬，时常去烧香祭拜，也难以消除内心的愧悔，所以他发愿，要常对养狗的人讲这个故事，劝大家要爱家中的狗，希望这可以消去他的一些罪业。
+
+　　唉！在人世间有情有义的人受到无情的背弃不也是这样吗？

+# 礼物送出去，用法也该交给对方
+
+<!-- daily-essay-id: 2026-11-10 -->
+
+<!-- wechat-digest: 礼物进入别人的生活，可能会有与送礼人设想不同的用法；认真感谢可以留住心意，把摆放、使用和调整的余地交给收礼的人，则能让这份心意少一些附带的负担。 -->
+
+　　送朋友一个杯子，后来发现他拿来插花，我觉得这杯子也算送对了。
+
+　　你买的时候，想的是他每天早上用它喝水。到了他家，杯子摆在窗边，里面插着几枝花。他喜欢那个颜色，只是更习惯用另一个大杯子喝水。
+
+　　东西确实融进了他的生活，走的却是另一条路。
+
+　　这时候如果问“怎么没拿来喝水”，朋友可能还愿意讲讲自己的习惯。再追问几次“这么好的杯子，拿来插花多可惜”，一份礼物就渐渐附上了使用说明，而且执行情况似乎还要接受检查。
+
+　　杯子在他家，怎么用的决定却还留在你手里。
+
+　　**既然是想让对方高兴，礼物到了他那里，就该有一点按他的生活重新安排的余地。**
+
+　　买礼物时，人很容易把一整幅画面都想好。送一本书，就想象朋友读完以后跟自己聊；送一个手账本，就想象他拿来记每天的生活；送一套茶具，就想象几个人以后坐在一起喝茶。
+
+　　这些想象可以是挑选时的乐趣。可真正收下礼物的人，还有自己的时间、空间和习惯。
+
+　　他可能正在读另外一本书，也可能更喜欢在手机上记事。茶具好看，但家里那张小桌子平时还要吃饭，只能先收进柜子里。
+
+　　礼物能不能照着想象使用，得跟这些事情一起商量。付款时的那一刻，并没有替朋友腾出读书的晚上，也没有让他家多出一张桌子。
+
+　　所以，“我花了这么多心思”，可以解释自己的期待有多大，却很难直接说明对方接下来该怎样生活。
+
+　　期待落空会失落，这很正常。认真挑了颜色，问过尺寸，甚至亲手做了很久，当然希望对方喜欢。
+
+　　但可以先分清，自己究竟在等什么。想知道心意有没有被收到，一句认真道谢、一次具体的回应，就能带来答案；想让礼物始终出现在对方生活的显眼位置，那已经是一个持续的要求。
+
+　　朋友收到围巾，说这个颜色挑得真好，出门时却仍然戴旧的那条，也可能只是旧围巾更厚，或是当天穿的外套更适合它。
+
+　　每次见面都检查围巾有没有戴，慢慢地，朋友出门前要考虑的就会多出一项：今天会见到谁，该拿哪件礼物出来。
+
+　　送礼原本想表达亲近，最后却让对方多做了一道准备工作。
+
+　　我更愿意在挑礼物的时候，把可能不合适的地方留得宽一点。尺寸拿不准就先问，拿得准也可以把换货的凭据留好，让对方知道可以换成合用的。
+
+　　问清楚会少一点拆包装时的惊喜，却可能多一点后来每天用得顺手的高兴。两种高兴，都值得考虑。
+
+　　尤其那些需要长期照顾、占很大地方的东西，更适合提前确认。自己觉得一大盆植物能让房间好看，对方可能连窗台都已经放满了。
+
+　　如果还得让他重新安排房间、研究怎么照顾，这份礼物里面，就已经包含了一项新的家务。先问清楚，才知道他有没有兴趣接下这件事。
+
+　　**送礼人的体贴，也包括允许自己的判断有偏差。**
+
+　　朋友发现尺寸不合适，愿意直接说出来，你就还有机会帮他换。要是每次听到这种反馈都受伤，他下次可能只会说喜欢，然后把东西收起来，再为收起来找一个更好听的理由。
+
+　　两个人都花了心思，只是用在了维持礼物很成功的样子上。
+
+　　收礼的一方，同样可以认真回应那份心意。说说自己看见的细节，感谢对方记得自己的喜好；拿不准会怎么用的时候，把话留在当下，也更诚实。
+
+　　“这个图案我很喜欢”，已经是一句完整的喜欢。顺口加上“以后天天都用”，却可能让双方开始期待一件自己还没想好的事。
+
+　　有些礼物确实承载着更特别的意思，比如亲手制作的纪念品，或者希望对方替自己留存的旧物。如果很在意它接下来怎样被保存，就提前把这层意思讲出来，让对方知道收下的是什么。
+
+　　对方愿意承担这份托付，双方就按说好的来。把特殊期待一直藏着，等看见东西被换了位置才生气，对方连判断的机会都没有。
+
+　　至于普通的日常礼物，过了一阵子不再合用，也可以让它有后续的去处。一个杯子陪过一段日子，后来闲下来了，这段陪伴仍然发生过。
+
+　　下次到朋友家，看见那个杯子插着花，可以问问花是在哪里买的。对方也许会告诉你，正好觉得这只杯子的颜色很搭，就把它放在了这里。
+
+　　这也是礼物被喜欢的一种样子。
+

+# 悲惨命运
+
+*毛姆*
+
+　　有些人，在拜访别人或晚上与人聊天的时候，总觉得告辞是一件很难的事。时间一分接一分地过去了，到拜访者觉得自己真的该走了的时候，他站起来吞吞吐吐地说：“呃，我想我……”紧接着主人就说：“噢，你这就要走吗？时间真的还早呢！”于是拜访者拿不定主意的尴尬就接踵而至了。
+
+　　在我所知的这类事情中，最悲惨的例子要数我可怜的朋友动三先生了。他简直不知道该如何从所拜访的人家里脱身。他是那么忠厚，又是那么规矩，从不愿失礼。
+
+　　在他放暑假的第一天下午，天空一片浅蓝，颜色很浅。他到一个朋友家里拜访。他在那儿聊了一会儿天，喝了两杯茶，然后好不容易鼓起勇气说：“呃，我想我……”
+
+　　可是女主人说：“噢，别急！动三先生，你真不能再多待一会儿吗？”
+
+　　动三从来都是说实话的。“噢，我能。”他说，“当然，我——呃——可以再待一会儿。”他留了下来，喝了十一杯茶。夜幕开始降临了，他再一次站起来。
+
+　　“呃，现在，我想我真的……”
+
+　　“你非要走吗？”女主人客气地说，“我还以为你可以留下来吃饭呢……”
+
+　　“呃，是可以的。”动三说，“假如……”
+

-　　每个 harness 用起来的体验很难明确感受到有多大，但是很多 harness 计费是差别相当大。比如同一个 Deepseek 模型，用下面这三个 harness，同一个任务计费能差十几块钱：Deepseek-TUI，Opencode，Deepseek Harness。第一个 Deepseek-TUI 缓存命中率常年没高过 98%，但是由 Deepseek 公司自己研发的 Deepseek Harness，缓存命中率基本上就没掉下过 98%。
+　　而上面这种模式，总有一个人要先踏出一步，这个人，我不能指望别人，那就只有自己了。
 
-　　还有一堆 Harness，比如 Codewhale，Pi，Cursor，使用感觉都不太一样。
+　　长久以来，我一直都这样想。
 
-　　第四个阶段：Agent 编排协作。
+　　没有换来对等的对待，没有收益。
 
-　　会用 Agent，基本上已经超过 90% 的人了，有意识挑一个专属于这个大模型的 Harness，基本上就超过 98% 了。因为对 AI 大模型来说，你给它发一把螺丝刀，还是发一把电动起子，或者全自动拧螺丝机，出来的效果肯定是不一样的，所以 Harness 挑选很重要（对你的钱包来说也很重要）。
+　　不过我想，从一开始就不应该期待有所谓的“收益”吧，毕竟人际关系并非投资。
 
-　　到 Agent 协作，实际上我都很少用。
+　　也许是工作耗费了我太多的心力，我已经无力维系这种模式了，不管出于什么原因，我决定进入低功耗模式。
 
-　　毕竟太烧钱了（笑。
+　　不再无谓地共情。不再自作多情。
 
-　　Agent 有很多种协作模式，和一个组织里类似。大体上分两类。
+　　我不清楚做出这个决定是否正确，也不清楚它是否属于一时兴起。
 
-　　审计监督模式。如果让一个 agent 既写代码又审代码，很容易马虎（看到有个研究说 Claude 审校自己写的代码会相对宽容）。既当裁判员又当运动员肯定有问题，那么就可以派另外一个 agent 监督和审计。最好不要用同一个 llm 的 subagent（子代理），因为同一个家里出来的，问题还是没解决。
+　　留给我的时间还有两个月。
 
-　　协同推进模式。也可以把一个任务丢给两个不同的 agent，让他们自己协作，分解任务，共同推进，比如可以下个 BAND，把两个 agent 拉到同一个 room 里。这种模式需要你自己监督，基本上不需要管细节，但是大方向一定要确保两个 llm 都没有跑偏。两个方向都错了，不仅要撤回相当麻烦，而且烧的那么多钱也都白费了。
+　　现在，确确实实，最后的狂欢。就像泰坦尼克号上，那三人最后的演奏一样。
 
-　　还有一些协作模式。用哪种模式，取决于项目的具体结构，高精度、重要或精细的项目容错率低，审计比较好，而一些玩具项目，不对外发布，自己一个人用，那么开发速度比较重要，就可以选择协同推进。
 
-　　到这里，第一个大方面，关于模型的方面，就说完了。
 
-
-
-　　第二个大方面，也是最后一个，是需要我们自己做的工作。
-
-　　不要想着一句话丢给 AI，然后等着收到一个满意的结果。
-
-　　如果不加以限制，最后交付的结果恐怕会相当一言难尽。
-
-　　第一件事最重要：明确需求。
-
-　　这是典型的、必须要人自己做的事情。
-
-　　许愿式编程、懒得动嘴型编撰报告，这些事我都干过。数次惨痛经历，得出了下面这条最重要的教训。
-
-　　与其在效率爆炸中自我感动，不如一开始把需求明确清楚，一条条地列出限制、需求、预期效果，最好能有具体例子。实在不知道自己有什么需求，也可以跟 agent 头脑风暴讨论，但就是不要开工。
-
-　　一个报告。
-
-　　写给谁看——领导个人？上级机构？外部监管？平级发函？
-
-　　用语措辞——正式公文？会议纪要？通信简讯？论文？
-
-　　具体内容——数据是否必须确切？还是可以估个大概？字数多少？需不需要配图？
-
-　　写代码就更不必多说了。
-
-　　采取什么架构，有没有速度要求，是否要清洗数据，是否对外提供服务，加多少功能，是否需要尽力保持 API 的稳定等等。
-
-　　需求相关的文档，必须自己手写，因为没有人清楚你想要什么，除了你自己。
-
-　　越详细越好。
-
-　　必要时可以和 agent 讨论。
-
-　　第二件，Prompt。
-
-　　原来有很多人喜欢搞提示词工程，写一堆，在我看来完全没有必要。
-
-　　而且提示词的淘汰速度，比 AI 本身还要快。
-
-　　所以这点，只有一条要做：明确身份。
-
-　　前面提到过，AI 吸收了全人类所有的知识精华，这也诞生了一个问题——你和它说想要个东西，它在思维链里可能跨了三四十个领域，不知道你要什么，尤其是涉及专有名词缩写的时候。
-
-　　维基百科都还要专门出个消歧义的页面呢。
-
-　　现在许多 llm 采用 MoE 架构（Mixture of Experts，混合专家架构），你提出的请求到 llm 内部后，会路由到处理这个问题的专家模块。所以，在这个基础上，生成阶段，清晰而不冗余的任务上下文，有助于让 top-k 专家集合更稳定地对应相关主题。
-
-　　现在很多 llm 自己拉起子代理的时候，也会给一个明确的身份。这样可以让分工清晰，防止子代理做出分工之外的越界内容。
-
-　　“你是一名敌对审校者，你的工作是尽力推翻用户设计的这份架构方案……”
-
-　　“你是一名中文教授，对于文章措辞、节奏把握、结构控制等有数十年经验……”
-
-　　当然，也有很多比较好的提示词，比如给 AI 说奥卡姆剃刀原则，或者奥威尔写作六原则。但这些提示词基本上只针对特定领域有限，而且每个 llm 的依从性都太一样，淘汰速度也很快，所以不是必选项。
-
-　　第三件，Skills。
-
-　　Skills 直译为技能，在 AI 领域实际上是指别人写好的文档。这个文档有可能是提示词，有可能是详细的教程，取决于这个技能为什么服务。
-
-　　比如大名鼎鼎的 grill-me.skill，全文实际上就四句话，还是英语的。但它能起到明确你需求的作用。
-
-　　很多人对自己的需求实际上不清楚，用这个 Skill，能够让 AI 在模糊的地方反复追问你，直到明确几乎所有边界条件。这样做出来的软件更可控、内聚，在执行过程中也更不容易发散。
-
-　　Skill 可以看成软件工程里的 Dependencies，或者软件包，它用起来很好用，所以别人愿意共享出来，让其他人也受益。实际上也是“不要重复造轮子”的一种体现。
-
-
-
-　　ok，那么写到这里，对于大模型和自己这两方面需要做的工作，就全部介绍完了。在网上的高阶内容，对一般人来讲实在很难用到，所以也不讲。
-
-　　看完了上面的内容，如果还是不知道怎么初步使用 AI，那么在这里可以给你一个明确的操作步骤：
-
-　　1. 明确自己的需求。最重要，也是最关键的一步。要用 AI 来做什么？
-
-　　2. 挑一个适合这个任务的 AI。比如 Gemini 更适合处理文本类型任务，Claude 更适合编码，等等。
-
-　　3. 去这个 llm 的官网申请一把 API Key，挑选一个适合它的 Harness（如有）。不是所有的人物都需要用到 API 或者 Harness，但是只要用到，体验肯定会比纯网页要好得多，至少不用自己复制粘贴。
-
-　　4. 根据需求，写好提示词。提示词越详细，指令越精确，一般来说效果越好。
-
-　　5. 视情况看看是否需要用到 Skills（可选）。
-
-　　6. 根据工程量大小，看看有没有必要上多 Agent 协作。
-
-　　7. 最后，Enjoy your project。
+　　当剪刀合上之后，我想，真正为自己而活，不寄希望于虚无缥缈的期待，也是另一种“留长发挑战”吧。

+# 随记 - 我会做菜了，可你在哪儿呢？
+
+## 写在前面
+
+<p style="color:#0f4c81; text-align:center; font-weight:bold; font-size:larger;">1608 字 | 想法 | 感触 | 生活 | 饮食</p>
+
+## 正文
+
+　　中午做饭。翻开冰箱，急冻室，里面还有一块上次去猪肉铺买回来的肉。买了一斤，当时只切了一半，剩下半块扔里面了。
+
+　　当时母亲说，做菜的时候提前给她打视频。
+
+　　母亲知道那个时候是我第一次做荤菜，从头开始做——不是直接把码好的肉和配菜一起倒进去炒熟那种。肉，要自己切、自己码。
+
+　　我也不知道当时脑子怎么抽了，要买块生肉。
+
+　　做的过程还算顺利，就是芹菜和青椒都买多了，炒了一锅，吃了有两三天才吃完，还有就是第一次切肉，没什么经验，肉丝切得有些厚。
+
+　　今天翻箱倒柜找食材，看见了剩下的半块，才意识到差点都忘了。
+
+　　我拿起它，犹豫了半晌。
+
+　　刹那间，我忽然想起大三的那个中午。
+
+　　当时我正上完课放学，她忽然打来电话，声音里带一丝慵懒。她说，在哪附近吃了一家很好吃的店，朋友推荐，她今天去试了一下，感觉还行，但没有家里的好吃。
+
+　　还说，她有些想念家里的味道。
+
+　　我当时也是脑子进水，笑了笑，跟她说：“你想吃什么嘛，我给你做。”
+
+　　我能很明显感受到电话那一头，直接愣住了。
+
+　　“嗯……嗯？”
+
+　　沉默了一秒钟，她开始笑：“你做不出来，”旋即又补充了一句，“很特殊的味道。”
+
+　　我也开始跟着笑。
+
+　　说这些话的时候，我正随着人流走。这所设施老旧的大学，仍用钟鼎敲响的声音作上下课的钟声，声音悠扬又古老。钟声随着周围学生的嬉笑打闹声穿过我，穿过电话。我抬头看了看高耸的第十教学楼，有树叶遮挡，只能通过罅隙看见建筑的顶端和天上的云。我的手捏着电话，放在耳边，就在川流不息的人群中驻足而立，看着天，说了后一句话：“万一我做出来的味道也很特殊呢？”
+
+　　两边都笑。
+
+　　“是好的那种就行。”
+
+　　“那肯定。”
+
+　　“下次试试吧。”
+
+　　“嗯，好。”
+
+　　她不知道的是，电话这边的这个男生，小时候因为做砸过一次荤菜，浪费了一锅肉，从此对做荤菜有着极大的心理阴影。此后几乎没有再做过荤菜，最多烧烧汤，做一做素菜。
+
+　　我不知道我出于什么动机，当时逞强说了那句话。
+
+　　就像延时摄影里那些不变的主角与风景，当时的我，站在人来人往的树下，还认认真真思考，之后该怎么办。都已经这样打脸充胖子了。
+
+　　母亲指导我怎样切肉、倒入香辛料、码肉的那个下午，我并未想太多。或许是因为没等我准备好，母亲的视频就提前打来了，也或许，是因为没有空思考，赶时间。而今天是周末。
+
+　　回过神来，我已经成功了一次了。而且，没有丝毫心理压力，只是一步一步地跟着母亲的指导。
+
+　　我没想到有这么简单。
+
+　　红油、胡椒粉、花椒粉、葱姜蒜末、干花椒碎、生抽、芡粉、料酒、豆瓣酱和醋。
+
+　　当时我还和母亲笑说，我可全听你的了，我觉得最难的就是这里了。
+
+　　我至今都不知道，母亲怎么隔着屏幕就能知道，哪些香辛料放多少，然后喊停。
+
+　　末了，她还说：“如果你想吃麻一点的，可以再倒点花椒油。”
+
+　　我没听，我说，等快出锅的时候再看看吧。
+
+　　“不放盐吗？”
+
+　　“出国的时候淡了再放，豆瓣酱已经有盐了，码肉的时候再放就咸了，腌进肉里之后还救不回来。”
+
+　　之后，我在家里又看了一遍。母亲按她自己的习惯，倒了哪些香辛料，倒多少。下过的时候，她把锅铲交给我，自己又去菜板上备其他菜。
+
+　　快出锅时，母亲又让我尝一下，看看少不少什么调料。我说，好像花椒味道好像淡了点。
+
+　　旋即，母亲又放了点。放的过程中，我一直在说，会不会太多了，会不会太多了。
+
+　　母亲却一直说，花椒面嘛，多放点无所谓，本来味道就不是很大。
+
+　　结果——麻得要死。
+
+　　那一锅肉，是母亲为我炒的，怕我在单位里嫌麻烦懒得弄。她提前炒好，用袋子小袋分装，让我带上，冻急冻室里，想吃的时候拿一袋出来解冻，热热就能吃。
+
+　　我有一次自己炸土豆丝，想吃点麻的，正好油也少了些，就放了花椒油，结果不小心放多了，也麻得要死。
+
+　　我想着这些笑出声。
+
+　　笑着笑着，又把那半块肉放下了。
+
+　　我现在确实懒得弄。母亲确实有先见之明。
+
+　　我拿了一小袋麻得要死的肉末豌豆出来，打开，往锅里倒，开始热。
+
+　　我已经会做肉菜了，那么你现在在哪里呢？佳芯小姐。
+

+

+

+　　现在许多 llm 采用 MoE 架构（Mixture of Experts，混合专家架构），你提出的请求到 llm 内部后，会路由到处理这个问题的专家模块。所以，在这个基础上，生成阶段，清晰而不冗余的任务上下文，有助于让 top-k 专家集合更稳定地对应相关主题。
+
+　　现在很多 llm 自己拉起子代理的时候，也会给一个明确的身份。这样可以让分工清晰，防止子代理做出分工之外的越界内容。
+
+　　“你是一名敌对审校者，你的工作是尽力推翻用户设计的这份架构方案……”
+
+　　“你是一名中文教授，对于文章措辞、节奏把握、结构控制等有数十年经验……”
+
+　　当然，也有很多比较好的提示词，比如给 AI 说奥卡姆剃刀原则，或者奥威尔写作六原则。但这些提示词基本上只针对特定领域有限，而且每个 llm 的依从性都太一样，淘汰速度也很快，所以不是必选项。
+
+　　第三件，Skills。
+
+　　Skills 直译为技能，在 AI 领域实际上是指别人写好的文档。这个文档有可能是提示词，有可能是详细的教程，取决于这个技能为什么服务。
+
+　　比如大名鼎鼎的 grill-me.skill，全文实际上就四句话，还是英语的。但它能起到明确你需求的作用。
+
+　　很多人对自己的需求实际上不清楚，用这个 Skill，能够让 AI 在模糊的地方反复追问你，直到明确几乎所有边界条件。这样做出来的软件更可控、内聚，在执行过程中也更不容易发散。
+
+　　Skill 可以看成软件工程里的 Dependencies，或者软件包，它用起来很好用，所以别人愿意共享出来，让其他人也受益。实际上也是“不要重复造轮子”的一种体现。
+
+
+
+　　ok，那么写到这里，对于大模型和自己这两方面需要做的工作，就全部介绍完了。在网上的高阶内容，对一般人来讲实在很难用到，所以也不讲。
+
+　　看完了上面的内容，如果还是不知道怎么初步使用 AI，那么在这里可以给你一个明确的操作步骤：
+
+　　1. 明确自己的需求。最重要，也是最关键的一步。要用 AI 来做什么？
+
+　　2. 挑一个适合这个任务的 AI。比如 Gemini 更适合处理文本类型任务，Claude 更适合编码，等等。
+
+　　3. 去这个 llm 的官网申请一把 API Key，挑选一个适合它的 Harness（如有）。不是所有的人物都需要用到 API 或者 Harness，但是只要用到，体验肯定会比纯网页要好得多，至少不用自己复制粘贴。
+
+　　4. 根据需求，写好提示词。提示词越详细，指令越精确，一般来说效果越好。
+
+　　5. 视情况看看是否需要用到 Skills（可选）。
+
+　　6. 根据工程量大小，看看有没有必要上多 Agent 协作。
+
+　　7. 最后，Enjoy your project。

+# 初步使用 AI
+
+## 写在前面
+
+<p style="color:#0f4c81; text-align:center; font-weight:bold; font-size:larger;">3392 字 | 人工智能 | 使用 | 经验</p>
+
+## 正文
+
+　　给公众号的读者看了这么多篇 AIGC 的内容，也是时候自己手写一点干货了。
+
+　　这篇打算写 AI 怎么用，但也仅限于初步使用。高级使用我也不怎么会……也许是因为高级使用还需要钱，而我没钱……
+
+　　阅读本篇文章需要读者具备一定基础的 AI 认知能力。
+
+　　一点就可以了，知道什么叫 GPT，Claude，Gemini，Grok，Deepseek，千问（Qwen），豆包什么的。
+
+　　还有，分得清 AI 大模型本身和他们背后的公司。比如 ChatGPT 是 AI 大模型，OpenAI 是它背后的公司，这俩不能混为一谈，这个在 Claude（AI 大模型）和 Anthropic（开发公司）之间体现得尤为割裂，Claude 本身对中国人没有恶意，谁来都一样聊天，但是 Anthropic 公司疯狂封国人账号，还搞各种恶心人甚至反人类的行为，比如到处搜刮古籍给 Claude 训练，训练完了之后一把火烧了之类的。
+
+　　扯远了，既然是 AI 使用，我们就专注在这个话题上面。
+
+　　现在的 AI 一般都是指大语言模型（Large Language Model，又叫 LLM，llm 在现在跟 ai 这个词差不多可以划等号），本质上是一个概率预测机。详细的基础知识就不介绍了，网上一大把，感兴趣的可以自己搜。
+
+　　第一阶段：最初的 AI，你只能跟它聊天。其实就是现在的网页版。
+
+　　现在可能 70-80% 的人都停留在这个阶段。也不一定是网页，有可能是某个软件里面的对话框，反正类似的形态。
+
+　　虽然 AI 吸收了全人类所有的知识（这也是个问题，待会儿会说），但是它还是只能给出指令，操作还是要人去操作。比如你让它写个报告，它只能给你输出内容，但是离变成报告这个文件，还要你复制粘贴，保存到某个路径下面。
+
+　　这时候，最先嫌麻烦的 AI Researcher 就想到了，给它接上手脚。
+
+　　第二个阶段：Agent 出现。
+
+　　为什么我还要自己操作？它如果要复制粘贴，自己去做不就好了？
+
+　　于是这帮 AI 研究者训练 AI 的时候就跟它说，如果你要调工具，那就按照我们给的格式写东西，比如【工具调用：搜索，参数：北京天气】（当然这只是一个例子），然后系统收到了你的请求之后，就会返回这个工具的调用结果给你。
+
+　　然后，他们塞了大把大把的工具进去，比如怎么建文件夹，怎么看 PPT，怎么上网，之类的。
+
+　　只要你有一个适合 LLM 住在里面的软件，那么 AI 就能替你干活儿了，报告不需要你复制粘贴，它写完内容会自动生成一个文件到你的桌面上。
+
+　　而这种软件，叫做 Harness。
+
+　　第三个阶段：Harness 专属化。
+
+　　AI 届现在有一个广泛承认的公式：Agent（智能体）= Model（大模型）+ Harness（马具/约束装置）。
+
+　　是不是感觉有点怪？为什么 Agent 范围更大，包括了 Harness？Harness 不应该是先诞生的吗？
+
+　　按顺序上来说，最初的 harness 肯定先于 agent 诞生，但现在我们谈到的是——harness 专属化。
+
+　　刚开始大家都觉得每个 harness 都差不多，codex 啊，claude code 啊，zcode 之类的。
+
+　　那不行，公司一想，这样怎么能吸引到别人来用我的模型呢？于是就都在各自的 harness 中添加一些只有自己的模型才能享受到的功能。
+
+　　算是一种隐形的商战吧。
+
+　　当然也不一定 harness 都是 llm 公司发布的，也有一些 harness 是第三方公司搞的，甚至还有一些纯纯是个人喜好开源的。
+
+　　每个 harness 用起来的体验很难明确感受到有多大，但是很多 harness 计费是差别相当大。比如同一个 Deepseek 模型，用下面这三个 harness，同一个任务计费能差十几块钱：Deepseek-TUI，Opencode，Deepseek Harness。第一个 Deepseek-TUI 缓存命中率常年没高过 98%，但是由 Deepseek 公司自己研发的 Deepseek Harness，缓存命中率基本上就没掉下过 98%。
+
+　　还有一堆 Harness，比如 Codewhale，Pi，Cursor，使用感觉都不太一样。
+
+　　第四个阶段：Agent 编排协作。
+
+　　会用 Agent，基本上已经超过 90% 的人了，有意识挑一个专属于这个大模型的 Harness，基本上就超过 98% 了。因为对 AI 大模型来说，你给它发一把螺丝刀，还是发一把电动起子，或者全自动拧螺丝机，出来的效果肯定是不一样的，所以 Harness 挑选很重要（对你的钱包来说也很重要）。
+
+　　到 Agent 协作，实际上我都很少用。
+
+　　毕竟太烧钱了（笑。
+
+　　Agent 有很多种协作模式，和一个组织里类似。大体上分两类。
+
+　　审计监督模式。如果让一个 agent 既写代码又审代码，很容易马虎（看到有个研究说 Claude 审校自己写的代码会相对宽容）。既当裁判员又当运动员肯定有问题，那么就可以派另外一个 agent 监督和审计。最好不要用同一个 llm 的 subagent（子代理），因为同一个家里出来的，问题还是没解决。
+
+　　协同推进模式。也可以把一个任务丢给两个不同的 agent，让他们自己协作，分解任务，共同推进，比如可以下个 BAND，把两个 agent 拉到同一个 room 里。这种模式需要你自己监督，基本上不需要管细节，但是大方向一定要确保两个 llm 都没有跑偏。两个方向都错了，不仅要撤回相当麻烦，而且烧的那么多钱也都白费了。
+
+　　还有一些协作模式。用哪种模式，取决于项目的具体结构，高精度、重要或精细的项目容错率低，审计比较好，而一些玩具项目，不对外发布，自己一个人用，那么开发速度比较重要，就可以选择协同推进。
+
+　　到这里，第一个大方面，关于模型的方面，就说完了。
+
+<br />
+
+　　第二个大方面，也是最后一个，是需要我们自己做的工作。
+
+　　不要想着一句话丢给 AI，然后等着收到一个满意的结果。
+
+　　如果不加以限制，最后交付的结果恐怕会相当一言难尽。
+
+　　第一件事最重要：明确需求。
+
+　　这是典型的、必须要人自己做的事情。
+
+　　许愿式编程、懒得动嘴型编撰报告，这些事我都干过。数次惨痛经历，得出了下面这条最重要的教训。
+
+　　与其在效率爆炸中自我感动，不如一开始把需求明确清楚，一条条地列出限制、需求、预期效果，最好能有具体例子。实在不知道自己有什么需求，也可以跟 agent 头脑风暴讨论，但就是不要开工。
+
+　　一个报告。
+
+　　写给谁看——领导个人？上级机构？外部监管？平级发函？
+
+　　用语措辞——正式公文？会议纪要？通信简讯？论文？
+
+　　具体内容——数据是否必须确切？还是可以估个大概？字数多少？需不需要配图？
+
+　　写代码就更不必多说了。
+
+　　采取什么架构，有没有速度要求，是否要清洗数据，是否对外提供服务，加多少功能，是否需要尽力保持 API 的稳定等等。
+
+　　需求相关的文档，必须自己手写，因为没有人清楚你想要什么，除了你自己。
+
+　　越详细越好。
+
+　　必要时可以和 agent 讨论。
+
+　　第二件，Prompt。
+
+　　原来有很多人喜欢搞提示词工程，写一堆，在我看来完全没有必要。
+
+　　而且提示词的淘汰速度，比 AI 本身还要快。
+
+　　所以这点，只有一条要做：明确身份。
+
+　　前面提到过，AI 吸收了全人类所有的知识精华，这也诞生了一个问题——你和它说想要个东西，它在思维链里可能跨了三四十个领域，不知道你要什么，尤其是涉及专有名词缩写的时候。

+# 打卡断了，练习还算数
+
+<!-- daily-essay-id: 2026-11-09 -->
+
+<!-- wechat-digest: 连续天数记录的是有没有中断，实际练习留下的作品、判断和熟练程度却另有积累；把漏掉的一天如实记下，再从已经做到的位置继续，才能让记录服务于原本想做的事情。 -->
+
+　　连续打卡归零的时候，先看看自己到底有什么归了零。
+
+　　假设你每天画一张速写，连着画了二十九天。第三十天临时有事，回到家已经很晚，想着明天再画，第二天打开记录，连续天数变成了零。
+
+　　那个数字看着挺刺眼。原本再过一天就能凑满一个月，现在又要从第一天开始。
+
+　　可把本子翻开，前面的二十九张画，明明都还在。
+
+　　这几天试过的线条、画坏后改过的比例、终于看出哪里别扭的那张椅子，也都各有各的结果。它们能帮后面的练习多少，要看你具体学到了什么，跟记录页面上的数字是两回事。
+
+　　“连续”这一项确实中断了，练习本却没有因此恢复成空白。
+
+　　我觉得，打卡最容易让人算糊涂的地方，就在这里。起初想做的是画画，后来每天最牵挂的，可能变成那个越来越长的数字。
+
+　　数字很清楚。一眼能看见多了一天，漏掉一天也立刻知道。至于画得有没有变化，得翻开本子，慢慢比较，判断起来麻烦多了。
+
+　　于是，容易看见的进展渐渐占了上风。今天到底观察到了什么，可以先放一边；那一格有没有亮起来，反倒成了睡前一定要确认的事。
+
+　　**连续天数能说明一件事：这段时间里，你一直有来。至于来了以后做了什么，还得另看。**
+
+　　为了保住记录，随便划两笔也按完成；有一天认真画了很久，却忘记登记，页面上仍然是空的。这两种情况摆在一起，就能看见记录与实际练习之间的距离。
+
+　　如果自己在意的是练习，评价那一天的时候，当然该把真正做过的事情算进去。
+
+　　打卡也有实在的用处。对一个刚开始的爱好而言，每天留一个位置、提醒自己坐下来，本来就值得做。很多东西得先动手，才谈得上后面的观察和改进。
+
+　　喜欢看记录一格格填满，也可以继续喜欢。那是自己花时间留下的痕迹，带来的愉快同样是真实的。
+
+　　只是中断之后，值得问的应当更具体一点：漏掉的这一天，会让接下来哪件事变难？
+
+　　如果只是忙了一晚，第二天仍然能拿起笔，那就把第二天的画接着画下去。那一页空着，忠实地记录当时发生了什么。
+
+　　如果已经连续几次挪到深夜，最后都因为太困作罢，就该看看时间安排。也许晚饭后那二十分钟更合适，也许原先定的篇幅让自己每次开始都觉得吃力。
+
+　　空白在这里提供了线索。把它只解释成“又失败了”，反而错过了可以调整的地方。
+
+　　而为了补回一天，强行让第二天画两倍，也要看自己到底想补什么。漏掉的那个晚上已经过去，多画一张可以是额外练习，却无法把昨天改成画过。
+
+　　如果加量让今天迟迟开始不了，那一天的空白就又拖住了第二天。原本拿起笔就能继续的事，突然多出一笔先要偿还的欠账。
+
+　　**今天的练习，可以从今天开始做。前面的成果照样保留，漏掉的记录也照样承认。**
+
+　　为了让这件事更容易看清，记录时可以再留一点连续天数以外的东西。比如保留每次的作品，每隔一段时间挑两张放在一起，看哪处观察更准确，哪处问题仍然反复出现。
+
+　　也可以写一句短短的说明：“今天终于发现，杯口画得太圆，是因为一直按想象中的样子画。”这句话未必适合变成漂亮的统计，却可能直接帮到下一张画。
+
+　　有了这些具体的东西，回头看一个月，才能同时看见来过多少次，以及这些次里发生了什么。
+
+　　如果某个挑战本来就以连续完成为规则，中断了就按规则算中断。自己报名时选的就是这个目标，重新开始也有它的意义。
+
+　　但这场挑战的成绩，与整个爱好里的收获，可以分开记。挑战这轮没完成，已经练过的内容仍然可以带进下一轮。
+
+　　拿着更熟悉的工具、更清楚的问题重新开始，和第一次摸索，本来就有差别。
+
+　　那本速写本翻到第三十张时，可以照实写上今天的日期。昨天空了一天，今天画桌边的杯子，顺便看看上次记下的杯口问题有没有改善。
+
+　　页面上的连续天数从一开始，本子里的画接着往后添。这两件事完全可以同时发生。
+
+<br />
+
+　　南国微雪 Miyuki
+
+　　2026 年 11 月 9 日

+# 我的妻子
+
+*季羡林*
+
+　　我因为是季家的独根独苗，身上负有传宗接代的重大任务，所以十八岁就结了婚。父母之命，媒妁之言，自不在话下。德华长我四岁。对我们家来说，她真正做到“毫不利己，专门利人”，一辈子勤勤恳恳，有时候还要含辛茹苦。上有公婆，下有稚子幼女，丈夫十几年不在家。公公又极难侍候，家里又穷，经济朝不保夕。在这些年，她究竟受了多少苦，她只是偶尔对我流露一点，我实在说不清楚。
+
+　　德华天资不是太高，只念过小学，大概能认千八百字。当我念小学的时候，我曾偷偷地看过许多旧小说，什么《西游记》、《封神演义》、《彭公案》、《施公案》、《济公传》、《七侠五义》、《小五义》等等都看过。当时这些书对我来说是“禁书”，叔父称之为“闲书”。看“闲书”是大罪状，是绝对不允许的。但是，不但我，连叔父的女儿秋妹都偷偷地看过不少。她把小说中常见的词儿“飞檐走壁”念成了“飞胆走壁”，一时传为笑柄。可是，德华一辈子也没有看过任何一部小说，别的书更谈不上了。她没有给我写过一封信，她根本拿不起笔来。到了晚年，连早年能认的千八百字也都大半还给了老师，剩下的不太多了。因此，她对我一辈子搞的这一套玩意儿根本不知道是什么东西，有什么意义。她似乎从来也没有想知道过。在这方面，我们俩毫无共同的语言。

+

+
+　　我活到了八十多，参透了人生真谛。人生无常，无法抗御。我在极端的快乐中，往往心头闪过一丝暗影：天下无不散的筵席。我们家这一出十分美满的戏，早晚会有煞戏的时候。果然，老祖先走了。去年德华又走了。她也已活到超过米寿，她可以瞑目了。
+
+　　德华永远活在我的记忆里。
+
+　　1995 年 6 月 21 日一 25 日

+# 看懂一个答案之后，试着换掉题里的条件
+
+<!-- daily-essay-id: 2026-11-08 -->
+
+<!-- wechat-digest: 顺着例子理解答案之后，只改动一个条件再独立做一次，可以看出自己掌握了哪些判断、遗漏了哪些前提；把卡住的具体位置找出来，后续学习才有明确的着落。 -->
+
+　　一个例子看懂了，可以试着改一个地方。
+
+　　数字换一下，顺序调一下，或者把原先默认成立的条件拿走，再看看刚才学到的办法还怎么用。很多“好像会了”，到了这里才开始变得具体。
+
+　　先说一个很小的例子。二十四个人参加活动，每桌能坐六个人，至少要几张桌子？四张，除一下就出来了。
+
+　　把二十四改成二十五。计算器给出四点几，现场却得准备五张桌子，因为多出来的一个人也得坐下。
+
+　　谁都知道桌子要按整张准备。可如果学的时候眼睛只盯着“人数除以每桌人数”，碰上刚好整除的例子，这一步判断就藏起来了。
+
+　　第一次做对，可能还看不出是否注意到了它。只改一个数字，就能把那个藏着的判断叫出来。
+
+　　**换条件，是给自己的理解安排一次小小的检查。**
+
+　　这件事放到学工具上，更容易看清。照着教程做一张报名表，跟着选中几行、点几个按钮，最后统计出了参加人数。数字一样，颜色也一样，看着很安心。
+
+　　现在在表格末尾新增两个人，再看看结果有没有跟着变。如果数字停在原地，就有一个值得回头查的问题：刚才统计的到底是整份名单，还是当时选中的那几行？
+
+　　教程原来的结果可以完全正确。是你换了一个条件，让原先看不出来的范围问题显现了。
+
+　　这个时候，继续重复旧例子，可能只是越来越熟练地选中同一块地方。把新增的两行放进去再试，才知道自己会不会处理名单继续增长的情况。
+
+　　我觉得，这种练习最有用的地方，是它能把一句很大的“我不会”，缩成一个比较小的问题。
+
+　　你已经会整理名单，也会完成原来的统计，只是还没弄清统计范围怎样随新增内容调整。下一次查资料，就能带着这个问题去找。
+
+　　比起重新从头看一遍全部教程，这样至少知道自己在等哪一句解释。
+
+　　换条件也有讲究。刚会一点，就同时换工具、换任务、换一套陌生材料，最后卡住，很难分清到底哪一处超出了现有理解。
+
+　　可以先保留大部分东西，只动一个会影响结果的地方。名单增加了人，就先只看新增的人有没有计入；这件事弄清了，再试着处理有人退出的情况。
+
+　　每次变化都对应一个问题，做完之后才容易说出，自己这次到底多会了什么。
+
+　　而且，动手之前，可以先猜一下结果。新增两个报名的人，人数应该多二；删掉一位已经退出的报名者，人数应该少一。
+
+　　如果做完以后结果与预想不同，回头核对，既可能是操作出了错，也可能是自己对问题的理解有误。至少手里已经有了一个可以比较的东西。
+
+　　其中也有些变化，只改了表面。把姓名换一批、表格换个颜色，确实能练习操作，但它们未必触动原先那条规则。
+
+　　真正值得试的，是那些会让选择发生变化的条件：数据增加，原先的方法能否继续覆盖；信息缺了一项，下一步还能不能照做；要求变了，结果需要跟着怎样改。
+
+　　试到后来，笔记也可以跟着换一种写法。在按钮顺序旁边，补一句自己当时为什么这么选，以及什么情况出现时要重新检查。
+
+　　“人数用这几行统计”旁边写上“名单新增后确认范围”，比只留一张做完的截图，更能提醒下次的自己。
+
+　　刚开始模仿，仍然很有用。跟着完整例子走一遍，才能知道这件事大致怎样完成。到了能做完的时候，再挪动其中一个条件，学习就往前多走了一步。
+
+　　如果只是临时处理一次任务，做到眼前够用，也可以收手。若准备以后经常做，或者替别人交付结果，花一点时间弄清变化之后怎么办，就更值得。
+
+　　练习用一份副本、一组自己编的名单就能开始。真实的报名记录还在原处，试错也有一个容易退回来的地方。
+
+　　下次看完一个例子，合上讲解之前，先挑一个条件改改。二十四个人变成二十五个人以后，你准备几张桌子，为什么？
+
+　　能把后面那个“为什么”讲清楚，再把新的安排做出来，这次学到的东西就有了更明确的边界。
