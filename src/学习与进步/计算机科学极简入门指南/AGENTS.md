# AGENTS.md

本文件是《计算机科学极简入门指南》系列的合作写作规范。

**任何 agent 在新增、修订本系列文章（尤其是“计算机组成原理”分册）之前，请先完整阅读本文件，并严格遵守，以保证不同 agent 产出的文本风格一致。** 若本文件与其它说明冲突，以本文件为准。

---

## 一、总体基调

- 面向**零基础**读者，自底向上，一步一步把零件搭起来：先造小部件，再用小部件拼大部件。
- **摒弃术语堆砌**：任何术语首次出现时，先用生活化语言把它讲明白，再给出名称与英文缩写，例如“程序计数器（PC，Program Counter）”。
- 语气**介于口语和书面语之间**：亲切、直接、有耐心，常用“我们”“你”，可以设问、可以打比方，但不油滑、不卖萌、不用 emoji。
- 不居高临下，也不神化知识；像一位耐心的同伴，带着读者边走边造。
- 可在合适处呼应本系列反复强调的四句话，但不要生硬堆砌：
  - 懒是人类进步的第一动力。
  - 在计算机科学里，没有什么问题是加一层解决不了的。
  - 人类所有知识都来源于好奇心和解决问题。
  - 所有庞大学科知识体量均由积累而成，不会一蹴而就。

## 二、章节结构（必须齐全，顺序固定）

1. `# 标题`：只写章节名，**不要**写“第X章”。
2. `## 复习`：用 `- 主题：一句要点` 的无序列表，回顾紧邻的前几章（通常 3 条，早期章节可更少）。**不要写章号。**
3. `## TL;DR`：2~4 条结论式短句，是读完整章后应当记住的东西，不是目录。
4. `## 正文`：写法见第三节。
5. `## 小结`
   - `### 知识点`：本章要点，用无序列表。
   - `### 参考资料`：编号列表，每条格式为 `[名称](链接)：一句话说明`。
   - `### 推荐`（可选）：视频等延伸材料。
   - `### 思考题答案（仅供参考）`：对照思考题逐一作答。
6. `## 协议`：固定文案，原文照抄：
   `本作品采用[知识共享署名-非商业性使用-相同方式共享 4.0 国际许可协议](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh)进行许可。`
7. `## 封面图`：一行 `![](图床链接)`，随后一行 `> 设计师 | 南国微雪`。

补充：**思考题**插在正文中，格式为居中加粗的 ` **思考题** `，后跟一个引用块 `> 　　……`；一章 1~2 道，必要时可编号为“思考题 1/2”。

## 三、正文写法

- 每个自然段以两个全角空格 `　　` 开头。
- 开头先承接上一章，或抛出一个问题、需求、生活场景，说明“为什么现在要讲这个”。
- 由问题驱动，基本节奏是：**提出问题 → 给直觉或类比 → 再形式化 → 落到电路或代码**。
- 善用生活类比（保险箱、楼梯双控开关、快递柜、翻译官……），但比喻之后一定要回到技术本体，不能停在比喻。
- 推导要一步一步来，宁可多写一句，也不要跳步；关键结论用 **粗体** 点出。
- 章末常用一句话预告下一章，形成连贯的叙事，例如“这就引出了下一章的主角——补码”。
- 可用 `###`、`####` 分级小节，但不要层层嵌套太深。
- 图示优先用图床图片；没有图片时，用 ASCII 示意图兜底。

## 四、语言与标点（重点，提交前务必自查）

- **正文一律使用中文引号 `“ ”`（双引号）与 `‘ ’`（单引号），并且前后必须成对匹配。**
- **禁止在正文中出现直角引号 `"`**；直角引号只允许出现在代码块、行内代码、命令、URL、HTML 属性等技术示例中。
- 引号嵌套：外层 `“ ”`，内层 `‘ ’`。
- 使用全角标点（，。：；？！、）；中文与拉丁字母、数字之间加空格，如 `1 KB`、`PC 保存`。
- **不使用任何 HTML 标签**（`<sub>`、`<sup>`、`<span>`、`<u>` 等一律不用）：
  - 上下标用 Unicode 字符：`²`、`³`、`ⁿ`、`₁₀`、`₂`。
  - 取反用组合上划线 `A̅`，也可写成 `~A`。
  - 强调统一用 Markdown 粗体 `**…**`。
- 数学符号沿用离散数学与布尔逻辑：与是乘法（可省略乘号）、或是加法、异或是 `⊕`。
- 代码、指令、二进制串、文件名等一律用行内代码 `` `…` ``。

## 五、内容与引用规范

- **正文中不写“第X章”**，改用概念式表述：`前面讲有符号数时`、`上一章`、`下一章`、`前面那个累加器`。这样章节增删调整时无需回头改引用。
- 需要跨章跳转时，用相对 Markdown 链接，例如 `[前面讲过的触发器](./第二十五章：触发器.md)`；mdBook 会自动把 `.md` 改写为 `.html`。
- 不引入超出当前进度的知识；若必须提前提及，注明“后面会讲”。
- 思考题要能运用本章知识，并尽量把前面几章串起来，不要考死记硬背。

## 六、文件与构建

- 章节文件名格式：`第X章：标题.md`（冒号为全角）。
- **文件名不得包含 ASCII 空格**（会导致 mdBook 解析 `src/SUMMARY.md` 失败）。确需空格时，在 `src/SUMMARY.md` 中把空格写成 `%20`。
- 新增或重命名章节后，同步更新 `src/SUMMARY.md`（只改本系列相关条目，不要动其它分册）。
- 提交前在仓库根目录执行 `mdbook build`，确认构建通过。
- 改动范围限定在《计算机科学极简入门指南》目录内，不要修改其它分册与无关文章。

## 七、提交

- 提交信息用中文：首行简短概括，正文分点说明“改了什么、为什么”。
