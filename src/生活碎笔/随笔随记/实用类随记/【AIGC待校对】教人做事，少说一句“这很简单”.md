# 教人做事，少说一句“这很简单”

　　“这很简单”有时候是教人做事最没用的一句话。

　　你想表达的可能是：别怕，我教你，很快就能学会。对方听到的却可能是：这么简单，你怎么还不会？

　　尤其当你已经说了第三遍，而他还卡在第一步的时候。

　　比如教一个没怎么做过饭的人炒菜。你说，油热了下锅，炒得差不多就放调料，熟了盛出来。

　　整个过程听起来确实没有几步。可他想问的是，怎么知道油热了？什么叫差不多？颜色变了算熟，还是还要等一会儿？

　　你省略掉的，恰好是他要学的。

　　等他犹豫着再问，你把铲子接过来，三两下做好了，顺口说：“你看，就这么简单。”

　　饭是做好了。至于下次他能不能自己做，还是不知道。

　　**熟练会让一些判断快到像是没有发生过。教别人时，却得把这些判断重新找出来。**

　　什么时候该动手，看到了什么才决定再等一等，出了什么变化就要停下来。这些东西，你可能已经不需要用语言想一遍，手上自然就做了。

　　但没学过的人没有这份自然。他看见的是你的动作，看不见你凭什么在这一刻做这个动作。

　　所以，把事情演示得很流畅，和把事情教清楚，中间还差一段路。演示的时候你做得越快，对方甚至越来不及知道自己没懂哪里。

　　我觉得，愿意教人，首先得承认一件有点麻烦的事：你得暂时放慢，回到自己早就不需要停留的地方。

　　这不一定舒服。你明明几分钟就能弄完，却要看着对方找按钮、认位置、重复一个动作。效率确实会降下来，不能一边说要让他学，一边又要求这一次就跟自己做得一样快。

　　不然，最后总会变成“算了，我来”。

　　然后下次又抱怨，怎么什么都要靠我。

　　当然，教不会不能一概怪教的人。学习的人也得动手、记住已经说明的东西、遇到不懂的地方开口。对方没有义务替自己完成全部理解，更不该因为愿意教，就被无限占用时间。

　　但既然这一次决定教，可以先把目标放小一点。今天到底要让他独立完成哪一步？先把这一小步走通，不必顺手讲完自己知道的所有门道。

　　比如教同事整理一份表格，不妨先让他找出需要处理的那几行，讲清楚为什么选它们，再做后面的操作。别一边飞快地改，一边补充另外五种更高效的方法。

　　你是在展示选择很多，他可能连眼前这条路都还没认出来。

　　讲完之后，也可以把操作交回去。让他照着做一次，看看卡在哪里。问一句“你会了吗”，很容易得到一句“会了”；真的开始做，才知道刚才看懂的是结果，还是过程。

　　如果又停在同一个地方，先问他现在准备做什么、正在找什么。有时缺的是一个词的意思，有时缺的是对前一步的理解，并不需要把整段话再大声重复一次。

　　音量变大，可不会自动多出一条说明。

　　还有一种常见的好心，是不停安慰：“别紧张，这个不会出问题的。”可如果操作确实会影响正在用的文件，担心就不是多余的。

　　能用副本练习，就先拿副本；哪一步可以重来，哪一步需要确认，提前讲清楚。知道做错之后怎么办，比被要求相信自己一定不会错，更让人敢动手。

　　这也不意味着所有事情都适合边错边学。涉及安全、重要资料或者别人利益的地方，该有人看着就看着，该经过正式训练就按要求来，不能为了让初学者放松，把风险说没了。

　　而学的人，也可以不接“这么简单还不会”这句话里的评价。

　　把问题问具体就好：“前面的我能做，到了这里，我不知道应该看哪个变化。”你不需要先为自己的理解速度道歉，再争取一次提问的资格。

　　如果对方现在没时间慢慢讲，也可以约另一段时间，或者请他指出可以先看的材料。一次讲不完，不用马上变成谁笨、谁没耐心的争论。

　　至于“简单”这个词，也不是从此不能用了。你可以说步骤不多，可以说先学会其中一部分就够用，也可以告诉对方哪里最容易出错。让人知道任务的范围，当然是帮助。

　　只是别拿自己的熟练程度，替别人规定学习应该花多久。

　　下次准备说“这很简单”的时候，可以试着往后接一句：“我刚才看的是这个，所以才做了下一步。”

　　多讲出那个原本被省掉的判断。对方需要的东西，可能就在这里。
