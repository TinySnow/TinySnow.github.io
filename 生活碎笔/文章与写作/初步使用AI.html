微雪博客

初步使用 AI

写在前面

3392 字 | 人工智能 | 使用 | 经验

正文

　　给公众号的读者看了这么多篇 AIGC 的内容，也是时候自己手写一点干货了。

　　这篇打算写 AI 怎么用，但也仅限于初步使用。高级使用我也不怎么会……也许是因为高级使用还需要钱，而我没钱……

　　阅读本篇文章需要读者具备一定基础的 AI 认知能力。

　　一点就可以了，知道什么叫 GPT，Claude，Gemini，Grok，Deepseek，千问（Qwen），豆包什么的。

　　还有，分得清 AI 大模型本身和他们背后的公司。比如 ChatGPT 是 AI 大模型，OpenAI 是它背后的公司，这俩不能混为一谈，这个在 Claude（AI 大模型）和 Anthropic（开发公司）之间体现得尤为割裂，Claude 本身对中国人没有恶意，谁来都一样聊天，但是 Anthropic 公司疯狂封国人账号，还搞各种恶心人甚至反人类的行为，比如到处搜刮古籍给 Claude 训练，训练完了之后一把火烧了之类的。

　　扯远了，既然是 AI 使用，我们就专注在这个话题上面。

　　现在的 AI 一般都是指大语言模型（Large Language Model，又叫 LLM，llm 在现在跟 ai 这个词差不多可以划等号），本质上是一个概率预测机。详细的基础知识就不介绍了，网上一大把，感兴趣的可以自己搜。

　　第一阶段：最初的 AI，你只能跟它聊天。其实就是现在的网页版。

　　现在可能 70-80% 的人都停留在这个阶段。也不一定是网页，有可能是某个软件里面的对话框，反正类似的形态。

　　虽然 AI 吸收了全人类所有的知识（这也是个问题，待会儿会说），但是它还是只能给出指令，操作还是要人去操作。比如你让它写个报告，它只能给你输出内容，但是离变成报告这个文件，还要你复制粘贴，保存到某个路径下面。

　　这时候，最先嫌麻烦的 AI Researcher 就想到了，给它接上手脚。

　　第二个阶段：Agent 出现。

　　为什么我还要自己操作？它如果要复制粘贴，自己去做不就好了？

　　于是这帮 AI 研究者训练 AI 的时候就跟它说，如果你要调工具，那就按照我们给的格式写东西，比如【工具调用：搜索，参数：北京天气】（当然这只是一个例子），然后系统收到了你的请求之后，就会返回这个工具的调用结果给你。

　　然后，他们塞了大把大把的工具进去，比如怎么建文件夹，怎么看 PPT，怎么上网，之类的。

　　只要你有一个适合 LLM 住在里面的软件，那么 AI 就能替你干活儿了，报告不需要你复制粘贴，它写完内容会自动生成一个文件到你的桌面上。

　　而这种软件，叫做 Harness。

　　第三个阶段：Harness 专属化。

　　AI 届现在有一个广泛承认的公式：Agent（智能体）= Model（大模型）+ Harness（马具/约束装置）。

　　是不是感觉有点怪？为什么 Agent 范围更大，包括了 Harness？Harness 不应该是先诞生的吗？

　　按顺序上来说，最初的 harness 肯定先于 agent 诞生，但现在我们谈到的是——harness 专属化。

　　刚开始大家都觉得每个 harness 都差不多，codex 啊，claude code 啊，zcode 之类的。

　　那不行，公司一想，这样怎么能吸引到别人来用我的模型呢？于是就都在各自的 harness 中添加一些只有自己的模型才能享受到的功能。

　　算是一种隐形的商战吧。

　　当然也不一定 harness 都是 llm 公司发布的，也有一些 harness 是第三方公司搞的，甚至还有一些纯纯是个人喜好开源的。

　　每个 harness 用起来的体验很难明确感受到有多大，但是很多 harness 计费是差别相当大。比如同一个 Deepseek 模型，用下面这三个 harness，同一个任务计费能差十几块钱：Deepseek-TUI，Opencode，Deepseek Harness。第一个 Deepseek-TUI 缓存命中率常年没高过 98%，但是由 Deepseek 公司自己研发的 Deepseek Harness，缓存命中率基本上就没掉下过 98%。

　　还有一堆 Harness，比如 Codewhale，Pi，Cursor，使用感觉都不太一样。

　　第四个阶段：Agent 编排协作。

　　会用 Agent，基本上已经超过 90% 的人了，有意识挑一个专属于这个大模型的 Harness，基本上就超过 98% 了。因为对 AI 大模型来说，你给它发一把螺丝刀，还是发一把电动起子，或者全自动拧螺丝机，出来的效果肯定是不一样的，所以 Harness 挑选很重要（对你的钱包来说也很重要）。

　　到 Agent 协作，实际上我都很少用。

　　毕竟太烧钱了（笑。

　　Agent 有很多种协作模式，和一个组织里类似。大体上分两类。

　　审计监督模式。如果让一个 agent 既写代码又审代码，很容易马虎（看到有个研究说 Claude 审校自己写的代码会相对宽容）。既当裁判员又当运动员肯定有问题，那么就可以派另外一个 agent 监督和审计。最好不要用同一个 llm 的 subagent（子代理），因为同一个家里出来的，问题还是没解决。

　　协同推进模式。也可以把一个任务丢给两个不同的 agent，让他们自己协作，分解任务，共同推进，比如可以下个 BAND，把两个 agent 拉到同一个 room 里。这种模式需要你自己监督，基本上不需要管细节，但是大方向一定要确保两个 llm 都没有跑偏。两个方向都错了，不仅要撤回相当麻烦，而且烧的那么多钱也都白费了。

　　还有一些协作模式。用哪种模式，取决于项目的具体结构，高精度、重要或精细的项目容错率低，审计比较好，而一些玩具项目，不对外发布，自己一个人用，那么开发速度比较重要，就可以选择协同推进。

　　到这里，第一个大方面，关于模型的方面，就说完了。


　　第二个大方面，也是最后一个，是需要我们自己做的工作。

　　不要想着一句话丢给 AI，然后等着收到一个满意的结果。

　　如果不加以限制，最后交付的结果恐怕会相当一言难尽。

　　第一件事最重要：明确需求。

　　这是典型的、必须要人自己做的事情。

　　许愿式编程、懒得动嘴型编撰报告，这些事我都干过。数次惨痛经历，得出了下面这条最重要的教训。

　　与其在效率爆炸中自我感动，不如一开始把需求明确清楚，一条条地列出限制、需求、预期效果，最好能有具体例子。实在不知道自己有什么需求，也可以跟 agent 头脑风暴讨论，但就是不要开工。

　　一个报告。

　　写给谁看——领导个人？上级机构？外部监管？平级发函？

　　用语措辞——正式公文？会议纪要？通信简讯？论文？

　　具体内容——数据是否必须确切？还是可以估个大概？字数多少？需不需要配图？

　　写代码就更不必多说了。

　　采取什么架构，有没有速度要求，是否要清洗数据，是否对外提供服务，加多少功能，是否需要尽力保持 API 的稳定等等。

　　需求相关的文档，必须自己手写，因为没有人清楚你想要什么，除了你自己。

　　越详细越好。

　　必要时可以和 agent 讨论。

　　第二件，Prompt。

　　原来有很多人喜欢搞提示词工程，写一堆，在我看来完全没有必要。

　　而且提示词的淘汰速度，比 AI 本身还要快。

　　所以这点，只有一条要做：明确身份。

　　前面提到过，AI 吸收了全人类所有的知识精华，这也诞生了一个问题——你和它说想要个东西，它在思维链里可能跨了三四十个领域，不知道你要什么，尤其是涉及专有名词缩写的时候。

　　维基百科都还要专门出个消歧义的页面呢。

　　现在许多 llm 采用 MoE 架构（Mixture of Experts，混合专家架构），你提出的请求到 llm 内部后，会路由到处理这个问题的专家模块。所以，在这个基础上，生成阶段，清晰而不冗余的任务上下文，有助于让 top-k 专家集合更稳定地对应相关主题。

　　现在很多 llm 自己拉起子代理的时候，也会给一个明确的身份。这样可以让分工清晰，防止子代理做出分工之外的越界内容。

　　“你是一名敌对审校者，你的工作是尽力推翻用户设计的这份架构方案……”

　　“你是一名中文教授，对于文章措辞、节奏把握、结构控制等有数十年经验……”

　　当然，也有很多比较好的提示词，比如给 AI 说奥卡姆剃刀原则，或者奥威尔写作六原则。但这些提示词基本上只针对特定领域有限，而且每个 llm 的依从性都太一样，淘汰速度也很快，所以不是必选项。

　　第三件，Skills。

　　Skills 直译为技能，在 AI 领域实际上是指别人写好的文档。这个文档有可能是提示词，有可能是详细的教程，取决于这个技能为什么服务。

　　比如大名鼎鼎的 grill-me.skill，全文实际上就四句话，还是英语的。但它能起到明确你需求的作用。

　　很多人对自己的需求实际上不清楚，用这个 Skill，能够让 AI 在模糊的地方反复追问你，直到明确几乎所有边界条件。这样做出来的软件更可控、内聚，在执行过程中也更不容易发散。

　　Skill 可以看成软件工程里的 Dependencies，或者软件包，它用起来很好用，所以别人愿意共享出来，让其他人也受益。实际上也是“不要重复造轮子”的一种体现。


　　ok，那么写到这里，对于大模型和自己这两方面需要做的工作，就全部介绍完了。在网上的高阶内容，对一般人来讲实在很难用到，所以也不讲。

　　看完了上面的内容，如果还是不知道怎么初步使用 AI，那么在这里可以给你一个明确的操作步骤：

　　1. 明确自己的需求。最重要，也是最关键的一步。要用 AI 来做什么？

　　2. 挑一个适合这个任务的 AI。比如 Gemini 更适合处理文本类型任务，Claude 更适合编码，等等。

　　3. 去这个 llm 的官网申请一把 API Key，挑选一个适合它的 Harness（如有）。不是所有的人物都需要用到 API 或者 Harness，但是只要用到，体验肯定会比纯网页要好得多，至少不用自己复制粘贴。

　　4. 根据需求，写好提示词。提示词越详细，指令越精确，一般来说效果越好。

　　5. 视情况看看是否需要用到 Skills（可选）。

　　6. 根据工程量大小，看看有没有必要上多 Agent 协作。

　　7. 最后，Enjoy your project。


　　南国微雪 Miyuki
